# PAGE Editor 0.0.2 版本计划与路线图

日期：2026-10-23（UTC+8）  
本次交付版本：**0.0.2 — 基础变量与文本引用**  
下一功能版本：**0.0.3 — 变量类型与字面量赋值**  
状态：本次交付范围包括基础字符串变量、原生配置保存和文本引用；实际构建、验证覆盖、未运行事项及最终文件状态分别记录。0.0.3 尚待单独确认实施范围和开始编码。

## 1. 最终开发目标

开发基于 Godot、能够构建为独立桌面程序的 PAGE Editor。用户直接运行 Windows 或 Linux 发布程序，完成 Dialogic 内容创作、资源管理和运行预览，无须打开 Godot 编辑器来运行 PAGE Editor。

1.0.0 必须实现 **Dialogic 2.0-alpha-20 的全部功能**，覆盖事件及全部属性、运行子系统、创作面板、项目设置、资源管理和自定义扩展，生成与该版本完全一致标准的代码、配置、资源和内容文件。支持部分事件、文件能够打开或功能按钮可见，均不能代替完整目标。

固定依赖为 Godot **4.7.1**、Dialogic **2.0-alpha-20**。界面必须基于用户已验证的 **dialogic_editor_ui_260903.zip**，保持整体场景、布局和主题，按功能作局部调整。

### 2.2 本版新增能力

| 编号 | 功能 | 本版功能与边界 |
|---|---|---|
| V01 | 变量入口 | 在既定 UI 的变量页面提供列表、名称、字符串初值、新建、编辑、改名、删除和保存操作；清楚显示未保存状态 |
| V02 | 字符串变量 | 仅创建扁平字符串变量；值可为空，支持中文、引号、反斜线及换行；数值外观如“001”仍保存为字符串 |
| V03 | 变量名称 | 使用 ASCII 标识符规则 `[A-Za-z_][A-Za-z0-9_]*`，非空且同层唯一；大小写敏感，`Name` 与 `name` 为不同变量；非法名称和重名明确报错，不静默改名 |
| V04 | 原生持久化 | 使用所选内容根的 `project.godot` 中 `[dialogic]` 的 `variables` 字典，即原生 `dialogic/variables` 设置；保存、关闭与重新打开后值一致 |
| V05 | 文本引用 | 旁白和基础角色台词支持 `{variable_name}`；重复或多个引用、空值和中文值按固定版本原生语义显示；.dtl 中始终保留引用文本 |
| V06 | 诊断 | 对非法名称、缺失变量、超范围引用及变量展开后出现的未支持文本功能给出明确诊断；时间线问题定位到物理源行列 |
| V07 | 预览初值 | 每次开始或 Restart 都使用当前内容根已保存初值的独立副本；未保存的变量变更需先保存或放弃；运行值不自动写回初值 |
| V08 | 文件保护 | 保存冲突、路径失效、权限失败、未保存切换、备份及不支持内容保护同样适用于变量配置 |
| V09 | 示例和说明 | 提供“定义称呼 → 保存 → 台词引用 → 重开 → 预览”的完整示例，并说明原生文件位置、范围和限制 |

改名和删除仅改变变量定义，不自动批量改写时间线；原有引用保留并重新诊断。跨文件引用重命名管理仍按 0.7.0 安排。

### 2.3 内容根与保存方案

- 所选内容根就是本版变量配置的归属范围；不向父目录寻找另一个工程，也不把 PAGE Editor 自身的配置当作目标配置。
- 已有 `project.godot` 时，仅更新 `[dialogic]/variables` 对应内容。无关设置、注释、格式和其他节保持原状；未修改保存保持原文件字节。
- 普通内容目录仍可打开和浏览，不自动生成工程文件。首次**显式保存变量**时，界面说明将创建最小原生 `project.godot`，包含配置版本及变量设置。该文件不是完整可运行游戏工程，也不添加目标主场景、插件或 autoload。
- 打开变量配置只读取数据，不执行目标工程的脚本、插件、主场景或单例。
- 保存前检查目标文件是否被外部修改、删除或替换；遇到冲突停止写入并保留草稿。覆盖保存保留原文件恢复副本。
- 既有数值、布尔值、变量文件夹等超出范围的数据只读显示；保存支持的字符串项时保留其原生值和类型，禁止同名覆盖。若遇到无法安全读写的配置，整体只读并说明原因，不生成删减版配置。
- 本版只处理上述基础变量设置。目标工程的设置覆盖机制、宿主依赖及完整配置管理属于后续项目功能；发现影响变量的 `override.cfg` 或平台专用变量设置时，给出范围提示并阻止声称已验证其运行等价性，必要时阻止相关预览。

变量原生位置为 ProjectSettings 的 `dialogic/variables`。PAGE Editor 在所选内容根内解析和更新相应配置文本，不将应用进程的全局 ProjectSettings 另存为目标工程。更新保留变量键之外的原始内容，无修改保存保持原字节。具体无损更新、冲突和失败恢复的实际验证状态见本版测试清单与独立记录。

本版变量配置最大为 4 MiB（含实际编码、BOM 和换行）；原生容器分隔符嵌套上限 64 层（含变量外层字典），超过时只读保护，避免原生序列化深度限制导致数据截断。单条展开后的预览文本最大为 4 MiB；超限时诊断，不生成截断内容。

### 2.4 文本与预览边界

仅支持简单字符串变量引用。本版不加入 Variable 赋值事件、运算表达式、条件分支、变量文件夹、宿主单例和方法调用；角色显示名仍是静态文本。

未知名称不能直接交给插件的表达式回退机制当作有效简单引用。转义花括号按指定版本的真实语义处理。预览前须检查变量替换后的文本：若字符串引入文本效果、随机文本、条件文本或其他尚未支持功能，应报范围诊断并阻止相关预览，不能私自转义改变语义后宣称等价。字符串原始值保留在配置中。

预览在上一轮清理完成后，把已保存初值的独立副本注入本轮 Dialogic 运行实例，再启动时间线。停止清理运行状态，运行值不回写目标变量配置；不临时改写 PAGE 的全局变量设置。开始、重启、停止、跨内容根和外部配置变化均纳入本版完整测试清单，实际状态分别记录。

字符串值中的普通字面花括号不一律拒绝；遵循固定插件按原文匹配顺序进行全串替换的实际行为，不另加递归求值。具体多变量替换顺序见测试用例 C-VAR-24；它属于原生字符串语义，不扩展表达式功能。

### 2.5 实施顺序与完成条件

1. 先保存本版范围、完整测试用例和初始恢复进度。
2. 用户明确说出“确认，开始写代码”后，按本范围实施变量数据、原生配置读写、UI、诊断和预览。
3. 新增或变更用例须先保存测试设计，再运行；生成双平台候选程序，冻结源码、程序和用例版本标识。
4. 对候选程序执行共有用例的 Linux 部分、Linux 专用用例及 Windows 包静态检查，逐项持久化结果；失败项修正后重建受影响产物并重测，保留失败历史。
5. 完成文档、用例状态及最终包一致性检查，以经过验证的同一候选程序打包，交付六个标准文件；若重新导出改变程序，按影响重测。
6. 发布说明明确本次实际验证环境、覆盖范围、未运行项目及 Windows 实机延期事项。

本版可用闭环：新建普通内容目录或选择工程根 → 定义 `player_name` 字符串 → 保存 → 在旁白或角色台词中使用 `{player_name}` → 关闭重开 → 独立程序预览正确显示 → 在指定 Dialogic 参考工程中按原生设置和文件正常读取、播放。

本版受环境条件限制的项目仍为未运行。发布说明列明缺口，后续满足条件时继续验证；这些缺口不视为完成，也不扩大为其他功能的测试豁免。

## 4. 全部功能的覆盖范围

### 4.1 事件与内部结构

| 选项与流程 | Choice、Label、Jump、Return、End；相应分支结构 | 0.2.0 |

Glossary 包含编辑器和运行能力，属于 0.6.0 的明确范围。其指定版本模块没有注册独立创作事件，因此不将其事件文件擅自列入标准事件集合。

## 6. 固定交付标准

### 6.1 每次版本交付的六个文件

| 顺序 | 0.0.2 文件名 | 必备内容 |
|---|---|---|
| 1 | PAGE_Editor_0.0.2_Source.zip | 完整可构建工程、依赖、资源、配置、构建工具、示例、许可和本版文档；根目录 PAGE_Editor_v0.0.2/ |
| 2 | PAGE_Editor_0.0.2_Windows_x86_64.zip | 实际导出的 PAGE_Editor.exe 及必要资源、平台说明和许可；根目录 PAGE_Editor_0.0.2_Windows_x86_64/ |
| 3 | PAGE_Editor_0.0.2_Linux_x86_64.zip | 实际导出的 PAGE_Editor.x86_64 及必要资源、平台说明和许可；根目录 PAGE_Editor_0.0.2_Linux_x86_64/ |
| 4 | PAGE_Editor_0.0.2_Release_Notes.md | 实际功能、变化、限制、构建与测试摘要、未运行事项、三份压缩包的大小及 SHA256 |
| 5 | PAGE_Editor_0.0.2_Plan_and_Roadmap.md | 最终目标、当前版本范围、完整路线图、关键约束、交付与测试规则 |
| 6 | PAGE_Editor_0.0.2_Testcases.md | 共有、Linux 专用、Windows 专用三节；每例有步骤、预期结果和运行状态，不填写实际结果明细 |

后续版本替换文件名中的版本号，维持同一六文件结构。实际程序、元数据、Source、README、CHANGELOG 和外部文档的版本一致；本版 Windows 数字版本为 0.0.2.0。

Source 的 README 必须保留集中产品配置及左上角 LOGO SVG 自定义章节，说明字段、路径、替换、同步、导出和打包步骤，以及 LOGO、应用图标和稳定用户数据目录的区别。

Source 内含本版路线图、发布说明和测试清单的相应文档。实际结果、截图、运行日志、恢复进度和对话 RECORD 单独保存，不作为新增的第七个标准发布文件，也不混入程序包。测试清单仅含状态，不嵌入结果证据。

产物大小和 SHA256 必须从最终文件计算。Release_Notes 不列自身哈希，Source 内的发布说明无需嵌入该 Source 最终包哈希，避免循环校验。包外发布说明列三包实际信息。

### 6.2 测试用例与状态

- 每个版本的 Testcases.md 都是该版本独立、完整的全量列表；重复用例也完整保留，不以增量清单或引用其他版本的用例代替。
- Testcases.md 只有三节用例：**共有、Linux专用、Windows专用**。共有用例分别列 Linux 状态、Windows 状态；单平台用例列一个状态。
- 每个状态只能是 **已运行 / 未运行**。本项目中的“已运行”表示该平台本用例全部样本满足预期，并已保存可恢复记录。失败、阻塞、中断、未执行均标为“未运行”。
- 失败记录的实际结果仍如实保存为失败；“视作未运行”不表示删除执行历史。重试通过后追加记录，不能覆盖先前失败证据。
- 用例包括前置条件、操作、预期结果和稳定编号；多样本逐一记录，任一样本未通过则整条仍为未运行。
- 先完成本版用例设计并保存，再运行。测试期间调整需求或用例时保存新修订，明确影响范围后重测；不能倒改预期以迎合实际输出。
- P0/P1 仅决定执行顺序；本版范围内的 P1 也需完成，不能用优先级豁免。
- 静态检查、单元验证、无界面运行和 GUI 操作分别记录。命令成功退出不能代替界面行为验证；Linux 上检查 Windows EXE 属性不算 Windows 实机测试。
- 用例数不等于运行次数；平台、样本和重试均分别留痕。不得设置未经确认的性能达标结论。
- 测试设计修订及定义指纹不含运行状态列；另记录每次保存后的完整文件 SHA256。仅更新状态不会使已通过用例失效，修改步骤、样本或预期才触发设计修订和影响评估。

### 6.3 每条测试后的持久化与恢复

顺序为：**执行一个用例/样本 → 保存实际结果和证据 → 确认保存成功 → 更新对应状态及进度 → 再执行下一项**。保存失败时暂停推进并重试保存，不能把只存在对话上下文中的通过算作恢复节点。

独立进度采用可追加的执行记录及当前检查点，至少记录：

| 字段 | 要求 |
|---|---|
| 运行序号 | 全局递增序号；同一用例重试也产生新序号 |
| 用例标识 | 用例编号、样本编号、设计修订/定义指纹及当次完整测试清单 SHA256 |
| 被测对象 | 源码/程序标识与 SHA256、平台、系统、工具链及 GUI/无界面/静态方式 |
| 时间与尝试 | 开始时间、完成时间、时区、尝试次数 |
| 实际结果 | 通过、失败、阻塞或中断；实际输出、预期对比及错误信息 |
| 证据 | 日志、截图或文件比较的保存位置及必要哈希 |
| 当前状态 | 按上述规则映射为已运行或未运行 |
| 后续动作 | 待修问题、重试条件、下一用例或样本 |
| 恢复信息 | 最后完整保存的运行序号、进度修订及保存完成标记 |

故障恢复后先读取最后完整保存的检查点和执行记录，核对版本、源码/程序哈希、用例修订及环境。仅对匹配且证据完整的通过记录恢复“已运行”；未落盘或中断项目重新执行。若修改代码或重建程序，评估影响并使相关通过状态失效，运行必要回归；不能沿用不对应交付二进制的通过结论。

`PAGE_Editor_0.0.2_Progress.md` 和独立测试结果持续记录实现、构建、逐项测试及最后持久化序号，作为故障恢复节点。这些工作记录不属于六个标准发布文件，也不进入程序包。

### 6.4 平台政策与发布门槛

- 从本次起，每个版本完成共有用例在 Linux 上的测试、Linux 专用测试、双平台实际导出及可执行的 Windows 包静态检查。
- **Windows 实机测试延后至 1.0.0 交付前统一执行。** 在此之前，Windows 专用用例以及共有用例的 Windows 运行状态保持未运行，并在发布说明中明确延期。无需逐个启动所有历史发布包，但 1.0.0 须覆盖此前积累的全部功能和当前用例。
- 1.0.0 不能仅补测 Windows 专用节；还须在 Windows 实机执行全部共有用例，完成真实启动、文件系统、UI 和原生预览验证。
- Linux 本版范围内的失败或未运行项不能计入完成；若受环境限制无法验证，应明确报告阻碍并保留未运行，不能凭静态阅读宣称通过。Windows 实机延期是明确的既定例外，不扩大为全部测试豁免。
- 最终交付包必须与测试证据的程序版本对应。打包后的文件完整性和运行资源需再次核对；只改变过程文档时不无理由重跑全部功能。
- Release_Notes 记录实际测试摘要及未运行事项；Testcases.md 只更新运行状态，详细结果留在独立进度与证据中。
