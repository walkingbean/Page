PAGE Editor 是独立对话创作程序。平台包包含独立可执行程序，无须通过 Godot 编辑器启动；Source 提供完整工程与构建工具。实际平台验证范围见下文。本版重点为基础字符串变量、原生配置保存和台词引用。

## 本版功能

- Variables 页面创建、编辑、改名和删除扁平字符串变量；初值支持中文、空字符串、引号、反斜线和换行，数值外观仍为字符串。
- 变量保存到所选内容根 project.godot 的原生 dialogic/variables 字典；支持关闭重开。普通目录在首次显式保存时才创建最小配置。
- 已有工程只更新变量设置，保留无关内容；超范围变量数据只读保留，文件损坏或无法安全更新时作保护。
- 旁白和基础角色台词使用 {variable_name} 引用；时间线保存引用原文，预览显示对应初值。非法名称、缺失引用和超范围语法有明确诊断。
- 每次开始或 Restart 都使用已保存初值；运行值不自动写回，未保存变量变更先保存或放弃。
- 修正停止和重启预览的清理顺序：先移除上一轮布局，再清空 Dialogic 状态，避免延迟文本完成信号访问已重置的事件索引。
- 原生 .dtl 文本编辑、旁白、注释、基础角色台词；原生 .dch 基础属性、单张默认 PNG、基本 join/leave；内容目录、查找和物理源行诊断。
- 未保存转换处理、外部文件冲突保护、保存恢复副本和超范围文件只读保护。
- config/branding.cfg 集中配置项目名、交付前缀、左上角 LOGO、应用图标和稳定用户数据目录；版本由 VERSION.txt 管理。

界面继续使用指定 UI 的场景、布局和主题，并在对应页面加入变量操作。应用版本为 0.0.2，Windows 数字版本为 0.0.2.0。

## 使用方法

Windows 解压后运行 PAGE_Editor.exe。Linux 解压后执行 ./PAGE_Editor.x86_64；解压工具未保留权限时先执行 chmod +x PAGE_Editor.x86_64。需要图形桌面和支持 Compatibility 渲染的驱动。

把 examples/variable_story/ 复制到可写目录，选为 Content Folder。在 Variables 修改 player_name 并保存，然后在 Timeline 打开 conversation.dtl，按 Play / F5。台词显示已保存称呼。Restart 恢复初值；Esc / F6 / Close 停止。角色与立绘示例见 examples/character_story/。

变量名采用 [A-Za-z_][A-Za-z0-9_]*，大小写敏感；改名或删除不自动批量改写其他时间线。移交内容到 Dialogic 工程时，仅合并目标 [dialogic] 节的 variables 设置，不能用示例的最小 project.godot 覆盖整个目标配置。完整说明见 Source 的 README 或平台包的 USER_GUIDE。

## 功能边界

本版不提供数值/布尔变量编辑、文件夹、Variable 赋值事件、运算表达式、条件、选项与跳转、多立绘、高级角色属性、UPDATE、动画变换、媒体、样式、术语、翻译或自定义扩展。角色显示名仍为静态文本。后续能力按完整路线图推进。

变量展开后若引入未支持的文本效果、随机/条件文本或富文本，相关预览受保护；不私自转义改变内容语义。读取目标设置不会执行其主场景、插件或宿主单例。覆盖设置及完整目标工程适配尚不在本版范围。

查找为单行字面匹配，没有替换、正则或跨行查询。.dtl / .dch 编码后上限 4,194,304 字节；PNG 上限 33,554,432 字节、单边 8192 像素、总像素 16,777,216；变量配置 project.godot 编码后（含 BOM 与换行）最多 4,194,304 字节，字典或构造器嵌套深度最多 64；变量展开后的单条预览文本最多 4,194,304 字节；目录扫描最多 20000 项、深度最多 64。各约束须同时满足，不构成性能承诺。

覆盖前保存恢复副本；不承诺断电或崩溃时的原子提交。用户内容根与应用资源根分离。程序未代码签名。

## 下一版本与最终目标

下一功能版本为 **0.0.3：变量类型与字面量赋值**。在现有字符串变量基础上加入数值、布尔值和类型编辑，支持时间线中的原生 Variable 字面量赋值及对应属性编辑，区分保存初值与本次运行值，并在后续台词中显示变化。运算、比较、逻辑表达式及表达式赋值安排在 0.0.4；0.0.5 推进单层条件，0.1.0 完成变量、表达式、条件与对应属性编辑。完整路线图见 docs/ROADMAP.md。

最终目标为完整独立创作、资源管理、运行预览，并生成符合 Dialogic 2.0-alpha-20 标准的代码、配置、资源与内容。0.0.3 的详细实施范围须另行确认；只有用户明确说出“确认，开始写代码”后才继续修改工程代码。
