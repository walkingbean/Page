# PAGE Editor 0.7.0 发布说明

本版主题为“项目与扩展”，以正式 0.6.0 Source 为工程基线。引擎固定为 Godot 4.7.1-stable，Dialogic 固定为 2.0-alpha-20。根 README 保持原始字节。下一计划版本见 [路线图](ROADMAP.md)。

## 本版功能

- 主界面新增 Project & Extensions 入口，提供 Settings、Resources、Source、Extensions、Run log 五个页面。
- 编辑目标原生 `project.godot`，支持数据类型校验、Autoload 名称/路径/启用标记/顺序，以及配置冲突保护、恢复副本和脏文档确认。保留未编辑内容、注释、换行和 BOM；对象构造表达式只读保留。
- 扫描目标资源，建立路径与 UID 映射、静态正向依赖、反向引用及行定位。资源改名前展示影响范围，检查过期计划、目标冲突和依赖完整性，提交时保留备份并处理失败恢复。
- 在 Source 中编辑目标脚本、场景和扩展索引，支持查找、滚动、原生保存及外部修改冲突保护。
- Signal / Call 通过目标原生 Dialogic 与 Host 单例执行；目标预览使用独立进程，支持主场景、时间线和选定场景，保留运行日志并提供停止入口。
- 使用原生扩展索引加载自定义事件、子系统、运行兼容的 DialogicEditor、立绘、动画、布局和文本效果。提供可编辑的 `examples/project_extensions` 示例。
- Export native project 将目标内容与固定依赖移交到新目录，保持原生 Godot/Dialogic 文件结构；已有目的目录不会被覆盖。

## 操作与边界

将示例或自己的项目复制到可写目录，通过 Content Folder 选择项目根。Project & Extensions 中的修改作用于目标项目。编辑后保存，再选择 Run project、Run selected 或 Open selected editor；Run log 提供原生进程输出。自定义编辑器可以自行选择输出文件，关闭或停止前应先保存其内容。

没有完整 Godot 编辑器接口的发布运行时只支持运行兼容扩展。依赖 `EditorInterface` / `EditorPlugin` 的编辑工具需在固定 Godot 编辑器中使用，运行日志会保留实际错误。此版没有集成任意扩展的通用可视化表单。

文本资源读取限制为 4 MiB；资源扫描限制为 20000 项、64 层目录。链接、根外路径、UID 冲突和不完整扫描会阻止不安全操作。动态拼接加载和未知二进制依赖无法完整静态分析，存在这些引用时不保证安全自动改名。预览支持所实现的图片、字体及 WAV/OGG/MP3 资源准备；其他自定义导入依赖需要其原生可用资源，不会被静默替代。

运行中的目标使用独立临时准备目录；原项目文件保持不变。目标脚本按原生 Godot 语义执行。固定 Dialogic 插件的行为保持原样，不通过修改插件源码模拟兼容。

## 构建、验证与交付

[BUILD.md](BUILD.md) 给出固定引擎、模板和原生运行资源准备步骤。[TESTCASES.md](TESTCASES.md) 包含 621 项独立用例定义及本版状态。逐项执行记录、失败尝试、截图、日志、脚本和恢复材料另放在同版本 Test Progress 包；只有所需阶段与检查全部完成的用例才标为“已运行”。

本版交付 Source、Linux x86_64、Windows x86_64、Test Progress 四个独立压缩包。执行证据不进入三个产品包；发布说明、路线图、完整测试清单只随 Source 提供。下载、校验和上传尝试详见本轮独立 RECORD。

## 已知差异与验证边界

- 原生 Save 事件将显式 `slot="Default"` 序列化为 `[save]` 后，再读取得到空槽；空槽会采用 latest/fallback 语义。PAGE 自身保存时显式保留槽参数，无法恢复另一个编辑器已省略的信息。原始参考工程已独立复现该差异，C-050-REF-01 不计为完成。
- 固定原生 History 在 `simple_history_save` / `full_history_save` 的四种布尔组合下，`get_full_state()` 都保存了两类已存在历史列表。727 原始参考工程已观察到该行为；本版执行806 C-050-HISTORY-03 在实际保存、读档后复现同一差异，该用例不计为完成。不要把关闭该设置描述为已验证能够排除历史状态。
- 构建字体导入异常与已验证的单线程导入诊断见 BUILD.md。异常历史没有因后续构建成功而删除。
- 实际测试采用 Dummy 音频后端检查解码、播放器、时间推进、模式、原生状态和信号，不宣称验证了声卡/扬声器输出。
